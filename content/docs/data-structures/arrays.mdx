An array stores an ordered sequence of values and gives each value an index. Its predictable layout makes random access fast and iteration cache-friendly.

## Operation costs

| Operation | Typical cost | Why |
| --- | --- | --- |
| Read by index | `O(1)` | The address can be calculated directly |
| Search unsorted data | `O(n)` | Values may need to be checked one by one |
| Append | `O(1)` amortized | Resizing happens only occasionally |
| Insert at the front | `O(n)` | Existing values must shift |

## Mental model

Think of numbered lockers placed side by side. You can jump directly to locker `7`, but adding a locker in the middle requires moving everything after it.

<Callout type="info" title="Use an array when">
  Order matters, indexed access is frequent, and most additions happen near the end.
</Callout>
