Sorting places values into an order that makes later work easier. The best algorithm depends on input size, existing order, memory constraints, and whether equal values must keep their original order.

## Useful comparison points

| Algorithm | Average time | Extra space | Stable |
| --- | --- | --- | --- |
| Insertion sort | `O(n²)` | `O(1)` | Yes |
| Merge sort | `O(n log n)` | `O(n)` | Yes |
| Quick sort | `O(n log n)` | `O(log n)` typical | Usually no |

## Stability

A stable sort preserves the original relative order of equal keys. This matters when records were already ordered by another field.

<Callout type="info" title="Nearly sorted data">
  Insertion sort can be a strong practical choice for small or nearly sorted inputs even though its general worst case is quadratic.
</Callout>
