## Komputer hanya mengerti angka

Di dalam komputer, semua hal (teks, gambar, musik, bahkan program) disimpan sebagai deretan **bit**, yaitu angka `0` dan `1`. Prosesor (CPU) hanya bisa menjalankan instruksi dalam bentuk bit ini. Bentuk inilah yang disebut **bahasa mesin**.

Contohnya, instruksi "tambahkan dua angka" di prosesor tertentu bisa terlihat seperti ini:

```txt title="Bahasa mesin (contoh)"
10110000 01100001
00000100 00000010
```

Manusia tentu sangat sulit membaca, menulis, dan memperbaiki instruksi seperti itu. Karena itulah dibuat **bahasa pemrograman**.

<Callout title="Definisi">
  **Bahasa pemrograman** adalah bahasa buatan yang memiliki aturan penulisan (**sintaks**) dan aturan makna (**semantik**) untuk menuliskan instruksi yang nantinya diterjemahkan dan dijalankan oleh komputer.
</Callout>

Bahasa pemrograman menjadi **jembatan**: manusia menulis instruksi dalam bentuk yang mudah dibaca, lalu sebuah program penerjemah mengubahnya menjadi bahasa mesin.

## Tingkatan bahasa pemrograman

Semakin dekat sebuah bahasa ke bahasa mesin, semakin **rendah** tingkatannya. Semakin dekat ke bahasa manusia, semakin **tinggi** tingkatannya.

| Tingkatan | Contoh | Ciri |
| --- | --- | --- |
| Bahasa mesin | `10110000 01100001` | Langsung dijalankan CPU, tetapi hampir mustahil dibaca manusia. |
| Bahasa tingkat rendah | Assembly: `MOV AL, 61h` | Setiap baris mewakili satu instruksi CPU. Cepat, tetapi panjang dan bergantung pada jenis prosesor. |
| Bahasa tingkat tinggi | C++, Python, Java | Mirip bahasa manusia dan matematika. Satu baris bisa mewakili banyak instruksi mesin. |

C++ dan Python sama-sama bahasa **tingkat tinggi**. Namun C++ masih memberi kendali yang cukup dekat ke perangkat keras, misalnya pengaturan memori. Karena itu C++ sering dipakai untuk program yang membutuhkan kecepatan, seperti game, sistem operasi, dan _competitive programming_.

## Dari kode menjadi program

Kode yang kita tulis disebut **kode sumber** (_source code_). Komputer tidak bisa menjalankannya secara langsung, jadi kode sumber harus diterjemahkan dulu. Ada dua cara utama menerjemahkannya.

### Compiler: diterjemahkan sekaligus

**Compiler** menerjemahkan **seluruh** kode sumber menjadi satu file program (_executable_) sebelum program dijalankan. Setelah dikompilasi, program bisa dijalankan berkali-kali tanpa diterjemahkan ulang. C++ memakai cara ini.

Jika ada satu saja kesalahan penulisan, compiler akan **menolak** membuat program dan menampilkan pesan error. Kesalahan ketahuan sebelum program berjalan.

### Interpreter: diterjemahkan sambil jalan

**Interpreter** membaca kode sumber dan menjalankannya **baris demi baris** saat program berjalan. Tidak ada file program terpisah yang dihasilkan. Python memakai cara ini.

<Pipeline

Misalnya baris ke-10 memanggil perintah yang namanya salah ketik, seperti `prnt` alih-alih `print`. Baris 1 sampai 9 tetap sempat dijalankan, dan kesalahan itu baru ketahuan saat baris ke-10 dicapai.

| | Compiler (C++) | Interpreter (Python) |
| --- | --- | --- |
| Kapan diterjemahkan | Sekali, sebelum dijalankan | Setiap kali dijalankan, baris demi baris |
| Hasil | File program (`.exe`) | Tidak ada file program |
| Kecepatan program | Umumnya lebih cepat | Umumnya lebih lambat |
| Salah ketik nama perintah | Ketahuan sebelum program jalan | Ketahuan saat baris itu dijalankan |

<Callout type="info" title="Sedikit lebih detail">
  Python sebenarnya juga menerjemahkan kode ke bentuk perantara bernama _bytecode_ sebelum menjalankannya. Saat menerjemahkan, Python memeriksa tata tulis seluruh file, jadi kesalahan seperti tanda kurung yang tidak ditutup langsung ditolak sebelum baris pertama dijalankan. Untuk tahap belajar ini, cukup pahami bahwa Python dijalankan oleh interpreter, sedangkan C++ dikompilasi menjadi program.
</Callout>

## Sintaks dan semantik

Setiap bahasa pemrograman punya dua jenis aturan:

- **Sintaks**: aturan _penulisan_. Mirip tata bahasa. Di C++, setiap pernyataan harus diakhiri titik koma `;`.
- **Semantik**: aturan _makna_. Kode yang sintaksnya benar belum tentu melakukan hal yang kita maksud.

Kesalahan sintaks disebut **syntax error**. Program tidak bisa dikompilasi atau dijalankan sama sekali:

```cpp tab="C++"
cout << "Halo"   // ✗ lupa titik koma, compiler menolak
```

```python tab="Python"
print("Halo"     # ✗ lupa tanda kurung tutup, interpreter menolak
```

Kesalahan makna disebut **logic error**. Program tetap berjalan, tetapi hasilnya salah. Kesalahan jenis ini lebih sulit ditemukan karena tidak ada pesan error:

```cpp tab="C++"
int panjang = 5, lebar = 3;
int luas = panjang + lebar;   // ✗ seharusnya dikali, bukan ditambah
cout << luas;                 // mencetak 8, bukan 15
```

```python tab="Python"
panjang, lebar = 5, 3
luas = panjang + lebar   # ✗ seharusnya dikali, bukan ditambah
print(luas)              # mencetak 8, bukan 15
```

## Program pertamamu

Tradisi belajar pemrograman dimulai dengan program yang menampilkan tulisan **Halo, dunia!**. Perhatikan perbedaan panjang kodenya:

```cpp tab="C++"
#include <iostream>
using namespace std;

int main() {
    cout << "Halo, dunia!" << endl;
    return 0;
}
```

```python tab="Python"
print("Halo, dunia!")
```

```txt title="Output"
Halo, dunia!
```

Program C++ terlihat lebih panjang karena ada beberapa baris wajib, seperti `#include`, `using namespace std;`, dan `int main()`. Untuk sekarang, anggap saja baris-baris itu sebagai "kerangka" yang selalu ada. Fungsinya dibahas di materi [Input & Output](/docs/cpp/input-dan-output).

## C++ atau Python?

Keduanya bagus dan konsep dasarnya **sama**. Yang berbeda adalah cara penulisan dan tujuan pemakaiannya.

| | C++ | Python |
| --- | --- | --- |
| Gaya penulisan | Lebih panjang dan ketat | Ringkas, mirip bahasa Inggris |
| Tipe data | Harus ditulis jelas (`int`, `double`) | Ditentukan otomatis |
| Kecepatan | Sangat cepat | Lebih lambat |
| Banyak dipakai untuk | Game, sistem, embedded, _competitive programming_ | Data science, machine learning, otomasi, web |

Belajar C++ lebih dulu membuat kamu memahami apa yang terjadi "di balik layar". Pemahaman itu memudahkan saat nanti mempelajari bahasa apa pun, termasuk Python.

## Rangkuman

- Komputer hanya menjalankan **bahasa mesin** (bit `0` dan `1`).
- **Bahasa pemrograman** adalah jembatan antara manusia dan komputer, dengan aturan **sintaks** dan **semantik**.
- C++ diterjemahkan oleh **compiler** menjadi program. Python dijalankan oleh **interpreter** baris demi baris.
- **Syntax error** membuat program gagal dijalankan. **Logic error** membuat program berjalan tetapi hasilnya salah.

  Program Python berikut seharusnya menghitung keliling persegi panjang dengan panjang 6 dan lebar 4. Rumusnya keliling = 2 × (panjang + lebar), jadi hasil yang benar adalah 20.

  ```python
  panjang = 6
  lebar = 4
  keliling = panjang + lebar
  print(keliling
  ```

### Sulit

<Soal no={8} level="sulit" judul="Kesalahan di baris terakhir">
  Ketiga program berikut seharusnya menampilkan `Satu`, `Dua`, dan `Tiga` di baris terpisah. Masing-masing punya satu kesalahan, tepat di perintah yang menampilkan `Tiga`. Untuk setiap program, tebak apa yang muncul di layar saat program itu dicoba dijalankan, lalu jelaskan alasannya.

  ```cpp title="Program A: tiga.cpp"
  #include <iostream>
  using namespace std;

  int main() {
      cout << "Satu" << endl;
      cout << "Dua" << endl;
      cout << "Tiga" << endl
      return 0;
  }
  ```

  ```python title="Program B: tiga_b.py"
  print("Satu")
  print("Dua")
  prnt("Tiga")
  ```

  ```python title="Program C: tiga_c.py"
  print("Satu")
  print("Dua")
  print("Tiga"
  ```

  <Petunjuk>
    Baca lagi kotak **Sedikit lebih detail** di bagian interpreter. Untuk Program B, tanyakan: apakah `prnt("Tiga")` salah secara bentuk penulisan, atau bentuknya benar tetapi nama perintahnya tidak dikenal?
  </Petunjuk>

  <Pembahasan>
    **Program A: tidak ada output sama sekali**, hanya pesan error dari compiler. Compiler memeriksa seluruh kode sebelum membuat program. Satu kesalahan saja membuat file program tidak terbentuk, jadi tidak ada baris yang sempat dijalankan.

    ```txt title="Output g++"
    tiga.cpp: In function ‘int main()’:
    tiga.cpp:7:27: error: expected ‘;’ before ‘return’
    ```

    **Program B: `Satu` dan `Dua` tampil, lalu program berhenti dengan error.** Bentuk `prnt("Tiga")` sah menurut aturan penulisan Python, yaitu sebuah nama yang diikuti tanda kurung. Python baru tahu bahwa nama `prnt` tidak ada ketika baris itu dijalankan.

    ```txt title="Output"
    Satu
    Dua
    Traceback (most recent call last):
      File "tiga_b.py", line 3, in <module>
        prnt("Tiga")
        ^^^^
    NameError: name 'prnt' is not defined. Did you mean: 'print'?
    ```

    **Program C: tidak ada output sama sekali.** Sebelum menjalankan baris pertama, Python membaca dan menerjemahkan seluruh file ke _bytecode_. Tanda kurung yang tidak ditutup melanggar aturan penulisan, jadi seluruh file ditolak.

    ```txt title="Output"
      File "tiga_c.py", line 3
        print("Tiga"
             ^
    SyntaxError: '(' was never closed
    ```

    Kesimpulannya, "baris demi baris" pada interpreter berlaku saat **menjalankan** kode. Pemeriksaan tata tulis tetap dilakukan untuk seluruh file sebelum program mulai berjalan.
  </Pembahasan>
</Soal>

<Soal no={9} level="sulit" judul="Laporan tiga teman">
  Tiga temanmu melaporkan masalah pada programnya.

  **Andi** (C++): "Waktu kompilasi muncul pesan berikut, dan file `.exe` tidak terbentuk."

  ```txt
  harga.cpp:6:22: error: expected ‘;’ before ‘cout’
  ```

  **Budi** (Python): "Programku berjalan tanpa pesan error dan menampilkan `49980`. Padahal harga Rp50.000 dengan diskon 20% seharusnya dibayar Rp40.000."

  ```python
  harga = 50000
  diskon = 20          # dalam persen
  bayar = harga - diskon
  print(bayar)
  ```

  **Citra** (Python): "Programku membagi uang kas sama rata ke semua anggota. Program sempat menampilkan dua baris, lalu berhenti dengan pesan `ZeroDivisionError: division by zero` waktu jumlah anggota kuisi 0."

  1. Tentukan jenis kesalahan Andi dan Budi, beserta alasannya.
  2. Kesalahan Citra tidak cocok disebut syntax error, tetapi juga tidak cocok disebut logic error. Jelaskan kenapa.
  3. Kesalahan siapa yang paling sulit ditemukan oleh pemilik programnya sendiri? Mengapa?

  <Petunjuk>
    Untuk setiap laporan, jawab dua pertanyaan: apakah program sempat berjalan, dan apakah muncul pesan error?
  </Petunjuk>

  <Pembahasan>
    | Laporan | Sempat berjalan? | Ada pesan error? | Jenis kesalahan |
    | --- | --- | --- | --- |
    | Andi | Tidak | Ya, dari compiler | Syntax error |
    | Budi | Ya, sampai selesai | Tidak | Logic error |
    | Citra | Ya, lalu berhenti di tengah jalan | Ya, saat program berjalan | Bukan keduanya |

    1. Kesalahan Andi adalah **syntax error**. Ada pernyataan yang tidak diakhiri `;`, sehingga compiler menolak kodenya dan program tidak pernah terbentuk. Kesalahan Budi adalah **logic error**. Programnya berjalan normal, tetapi rumusnya mengurangi harga dengan 20 **rupiah**, bukan 20 **persen**. Rumus yang benar adalah bayar = harga − harga × diskon ÷ 100.
    2. Bukan syntax error, karena kodenya lolos pemeriksaan dan program sempat berjalan. Buktinya, dua baris sudah tampil. Bukan logic error biasa, karena program tidak diam-diam memberi hasil yang salah, melainkan berhenti mendadak dengan pesan error. Kesalahan yang baru muncul saat program berjalan, sering kali karena data tertentu seperti pembagi 0, disebut **runtime error**. Jenis ketiga ini dibahas di [Membaca Error & Debugging](/docs/cpp/membaca-error-dan-debugging).
    3. Kesalahan Budi. Tidak ada pesan apa pun yang menunjuk kesalahannya. Budi hanya bisa tahu dengan membandingkan output program dengan jawaban yang sudah ia hitung sendiri.
  </Pembahasan>
</Soal>

<Soal no={10} level="sulit" judul="Program di komputer lain">
  Rina menulis `halo.cpp` lalu mengompilasinya di laptopnya menjadi `halo.exe`. Ia mengirim **hanya** `halo.exe` kepada Dodi, yang komputernya memakai jenis prosesor berbeda. Program itu tidak bisa dijalankan di komputer Dodi. Setelah Rina mengirim `halo.cpp` dan Dodi mengompilasinya sendiri, programnya berjalan normal.

  1. Mengapa `halo.exe` dari Rina tidak bisa berjalan di komputer Dodi, padahal `halo.cpp` yang sama bisa?
  2. Sari menulis program yang sama dalam Python, `halo.py`. File apa yang perlu ia kirim, dan apa yang harus sudah terpasang di komputer penerimanya?
  3. Dilihat dari sisi penerima, sebutkan satu kelebihan dan satu kekurangan mengirim `halo.exe` dibandingkan mengirim `halo.py`.

  <Petunjuk>
    `halo.exe` berisi bahasa mesin. Ingat lagi tabel tingkatan bahasa: bahasa mana yang bergantung pada jenis prosesor, dan bahasa mana yang tidak?
  </Petunjuk>

  <Pembahasan>
    1. `halo.exe` berisi bahasa mesin, dan instruksi bahasa mesin dibuat untuk jenis prosesor tertentu. Prosesor Dodi memahami kumpulan instruksi yang berbeda, jadi deretan bit di `halo.exe` tidak bisa ia jalankan. Sebaliknya, `halo.cpp` ditulis dalam bahasa tingkat tinggi yang tidak terikat jenis prosesor. Compiler di komputer Dodi menerjemahkannya menjadi bahasa mesin untuk prosesor Dodi sendiri. Perbedaan sistem operasi, misalnya Windows dan Linux, juga bisa membuat file program tidak cocok walaupun prosesornya sama.
    2. Sari cukup mengirim `halo.py`. Komputer penerima harus sudah memasang interpreter Python, karena interpreter itulah yang menerjemahkan dan menjalankan kodenya di sana.
    3. Contoh jawaban:

    | | Mengirim `halo.exe` | Mengirim `halo.py` |
    | --- | --- | --- |
    | Kelebihan | Penerima tidak perlu memasang compiler, cukup menjalankan. Programnya juga cepat. | Satu file yang sama bisa dipakai di berbagai jenis komputer. |
    | Kekurangan | Hanya cocok untuk jenis prosesor (dan sistem operasi) tertentu. Untuk komputer jenis lain, kodenya harus dikompilasi ulang. | Penerima harus memasang interpreter Python, dan programnya umumnya lebih lambat. |
  </Pembahasan>
</Soal>
